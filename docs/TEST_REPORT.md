# 开发期实测记录（2026-10-21，云端 Ubuntu 24.04 x86_64，Xvfb 1920×1080＋PulseAudio）

以下数字均为开发会话中实际测得，非估算。

## 资源占用
| 项目 | 结果 |
|---|---|
| 界面程序体积 | x86_64 126 296 字节，aarch64 114 280 字节（strip 后） |
| 界面进程内存 | RSS 约 17–24 MB（空闲 17 MB，录制中约 20–23 MB） |
| ffmpeg 录制进程内存（1080P 全屏 24 帧） | 标准档：调参前 199 MB → 调参后 147–159 MB；流畅档（ultrafast）约 74–100 MB |
| 依赖 | 只 NEEDED libX11.so.6、libc、libm、libpthread、libdl；glibc 需求上限 GLIBC_2.17 |

## 音画同步与混音
| 测试 | 结果 |
|---|---|
| 6 秒片段（`tests/manual/segtest.py`），无探测参数 | 视频只有 2.0–3.6 秒（开头被探测吞掉） |
| 加 `-probesize 32 -analyzeduration 0` 后 | 6.04–6.08 秒，与墙钟一致 |
| 同步测试（`synctest.sh`：屏幕变白与 440 Hz 同时开始，中途暂停 1.5 秒） | 修正前声音比画面晚约 0.2–0.4 秒；改为全局时间轴＋`-copyts/-itsoffset` 后，MP4 与 MKV 偏差均 ≤ 0.04 秒 |
| 40 秒漂移测试（`drift.sh`，系统声音＋麦克风） | 起点偏差 0.05 秒，38 秒处偏差 0.06 秒，无累积漂移 |
| 混音（`mixcheck.py`，440 Hz 系统声音＋880 Hz 管道麦克风） | 全程两路频率均在，最小 10 ms RMS 约 4 200，无断音 |

注：PulseAudio 的 `module-sine-source` 每 2 秒成批吐数据，不适合当麦克风测试源；改用 `module-pipe-source` 按墙钟送样本（`feedmic.py`）。`null-sink.monitor` 有约 1 秒的固定启动延迟，属于测试环境特性。

## 功能
| 测试 | 结果 |
|---|---|
| 全屏、区域（900×400、690×450）、窗口单击选择 | 输出尺寸与所选一致，偶数对齐 |
| 暂停／继续 | 两段合并，暂停时段不计入时长；段收尾 0.1–0.5 秒 |
| 720P 缩放、流畅档 MKV、15 帧 | 1280×720，15 fps，无声单流 |
| 高清 30 帧两路声音 | 1920×1080，29.8–30 fps，AAC 48 kHz 双声道 |
| 界面进程被 `kill -9` | 重启后自动合并为 `…_恢复.mp4`（加 `-flush_packets 1` 前分段为 0 字节、无法恢复） |
| 引擎去掉执行位 | 自动复制到 `~/.cache/shiying/ffmpeg` 并正常录制 |
| 第二实例 `--toggle` | 转发给已运行实例，进程数保持 1 |
| arm64 引擎（qemu-aarch64-static 包装为 bin/ffmpeg） | 640×360 区域、10 帧、两路声音，录制、暂停、合并全部通过 |
| deb 安装（x86_64）／免安装 `安装到菜单.sh` | /opt/拾影录屏 与菜单项、桌面图标正确；中文路径下自检、录制、保存通过 |
| 界面缩放 `SHIYING_SCALE=1.5` | 布局按比例放大，无裁切 |
